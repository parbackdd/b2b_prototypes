# B2B AI Concept Prototypes

Four static, clickable prototypes translate workshop needs into tangible B2B operational workflows. All names, cases, customers and operational data are synthetic. The prototypes are not connected to production systems and do not represent approved solution designs.

## Prototypes

| Capability | Prototype | Demonstrated human-control boundary |
|---|---|---|
| Content and documentation | [Incident Report Drafting](https://parbackdd.github.io/b2b_prototypes/) | AI creates a traceable draft; the incident manager edits and approves it. |
| AI-assisted troubleshooting | [Guided Technical Diagnosis](https://parbackdd.github.io/b2b_prototypes/troubleshooting/) | AI presents evidence-backed hypotheses and checks; a specialist diagnoses and chooses the next action. |
| Business quality and anomaly detection | [Quality Exception Review](https://parbackdd.github.io/b2b_prototypes/quality-anomaly/) | AI selects and explains exceptions; people decide corrections, clarification and ownership. |
| Operational monitoring and control | [Operational Attention Desk](https://parbackdd.github.io/b2b_prototypes/operational-monitoring/) | AI groups and prioritises signals; people acknowledge, assign, dismiss or initiate an existing escalation process. |

Open the [prototype portfolio](https://parbackdd.github.io/b2b_prototypes/prototypes/) to navigate between all four concepts.

## Run locally

Serve the repository root with any static HTTP server:

```sh
python3 -m http.server 8000
```

Then open <http://localhost:8000/>.
